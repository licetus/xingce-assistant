### 架构上值得记住的几个决策

1. **判题全在云端，下发的题目不含 `answer`** — 题库是唯一资产，从源头防拖库。
   「即时解析」用逐题提交（instant 模式）实现，答案在作答后才下发，安全性不变。
   `answer` 云函数按 items 数组长度自动适配 instant/batch 两种模式。

2. **事务只包「必须强一致」的部分** — 云开发事务有执行时间上限，20 题全量写入会产生 60+ 次操作。
   只有 wrong_book + users.stats 进事务；records（只增日志）和 questions.stat（难度校准）放事务外异步写。

3. **`utils/cloud.js` 是唯一出口** — 全项目禁止直接 wx.cloud.callFunction / wx.cloud.database。
   将来迁自建后端只改这一个文件。

4. **错题本列表放主包** — tabBar 的 pagePath 必须指向主包页面，四个 tab 都得在主包。

5. **`config.audit_mode` 审核开关** — 提审时云端改配置隐藏排行榜/邀请/奖励，不用重新发版。

6. **微信关系链能力已收紧** — getFriendCloudStorage 等非游戏类目基本拿不到好友数据，
   好友榜改为「分享链接绑定 inviteBy 自建邀请关系」。

Git：`main`（线上，受保护）+ `develop`（体验版）+ `feature/*` + `hotfix/*`。
hotfix 必须同时合回 main 和 develop。当前在 develop。

### 核心认知

**小程序存在三套互不同步的版本体系**：
1. 代码版本（Git）— 即时
2. 平台版本（微信后台）— 1~7 工作日，**要审核**
3. 业务版本（config 集合 + 云函数）— **即时，且不需要审核**

**云函数是变相热更**：云开发支持版本 + 别名 + 流量分配，改云函数几分钟生效不用提审。
代价是必须向前兼容——小程序用户不会同时升级，云函数接口只加字段不删字段，废弃留 2 个版本周期。

### 踩到的坑（已修复）

`compareVersion('v1.2.3', '1.2.3')` 原本返回 -1。原因：'v1' 被 parseInt 解析成 NaN → 0。
Git tag 惯例带 v 前缀，而微信后台版本号是手填的，两者不一致会导致**强制更新静默失效**——
不报错，极难排查。已加 `normalize()` 去掉 v/V 前缀并 trim，18 个用例全通过。
