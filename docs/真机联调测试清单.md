> 本文档是「行测小助手」V1.0 真机联调的标准操作流程。
> 任何接手联调的人，**先读这份文档**，再扫码进入小程序。

## 1. 主链路测试（4 条必跑）

### 链路 A：登录 + 个人信息

**目标**：验证 wx.login → login 云函数 → users 集合写入 → 个人信息回显。

| 步骤 | 操作 | 预期 | 异常排查 |
|---|---|---|---|
| A1 | 微信开发者工具点"预览"→ 真机扫码 | 进入首页 | 扫码失败 → 检查 AppID 是否为正式值 |
| A2 | 首页应有"登录"按钮或自动登录 | wx.login 自动调用，无感 | 401 → OPENID 没拿到 |
| A3 | 进入"我的"页面 | 显示 openid 简码、统计数字全 0 | 找不到 user → login 云函数没建档 |
| A4 | 点"编辑资料" → 选头像 + 改昵称 → 保存 | 头像/昵称显示正确 | `chooseAvatar` 不触发 → 基础库版本低 |
| A5 | 杀掉小程序，重开 | "我的"页面仍显示头像昵称 | 数据丢了 → users 集合 ADMINONLY 不让前端写，没走云函数 |

**云函数日志关注**：`login` / `user` 函数的最后 10 条日志（开发者工具 → 云开发 → 云函数 → login → 日志）

---

### 链路 B：答题 → 判题 → 错题本

**目标**：验证 question 云函数下发 → 用户作答 → answer 云函数判题 → 错题本写入。

| 步骤 | 操作 | 预期 | 异常排查 |
|---|---|---|---|
| B1 | 首页点"专项刷题"或"题库" | 模块卡片列表 | 进不去 → 跳转方式错（navigateTo 跳 tabBar 页必失败） |
| B2 | 选一个模块（如"言语理解"）→ 点"开始刷题" | 进入题目页，10~20 道题 | 题目加载失败 → question 云函数查库超时 |
| B3 | 第 1 题选 A，提交下一题 | 第 2 题加载 | 卡死 → 网络断 |
| B4 | 全做完提交 | 显示"答对 X 题"详情页，包含每题解析 | "成绩保存失败" → answer 事务超时（标准版 20s 够用） |
| B5 | 回首页 → 进"错题本" | 显示刚才答错的题（如果答错了的话） | 错题不显示 → wrong_book 写失败 |
| B6 | 重做错题（选错的那题）→ 答对 2 次 | 该题从错题本消失（标记 mastered） | mastered 没动 → answer 事务里的 rightStreak 累加没生效 |

**重点关注**：B4 步的"详情页"应包含三件套——`correct` 布尔、`answer` 字段（标准答案）、`analysis` 字段（解析）。
**如果只看到 correct 没看到 answer**：前端提前泄露了答案给客户端（违反「判题全在云端」原则），必须立刻修。

**云函数日志关注**：`answer` 函数耗时（标准版允许 900s，个人版锁 3s 时会超时）

---

### 链路 C：打卡 + 排行榜

**目标**：验证 timer dailyTask 生成题目 → checkin 云函数打卡 → rank 缓存刷新。

| 步骤 | 操作 | 预期 | 异常排查 |
|---|---|---|---|
| C1 | 首页 → "打卡"按钮 | 弹出今日 10 题（如果 daily_task 集合今日已生成） | 题目为空 → daily_task 没数据 |
| C1.5 | （若 daily_task 空）查看触发器是否绑定 | 控制台 → 云函数 → timer → 触发器管理 | 3 个触发器都在 |
| C2 | 做完打卡题提交 | 显示「已打卡 X/10，连续 N 天」 | 打卡失败 → checkin 云函数异常 |
| C3 | 同一手机第二次点"打卡" | 提示"今日已打卡" | 没拦住 → checkin 重复打卡逻辑漏了 |
| C4 | 第二天再点"打卡" | "连续 N 天" 加 1 | 没加 → date 比较用了 UTC 而非东八区 |
| C5 | "排行榜"按钮 → 看到自己 + 其他测试号 | 按正确率倒序，自己在最上（如果全对） | 榜单为空 → rank_cache 没刷新 |

**关于 daily_task 的关键点**：

- timer 触发器每天 00:05 跑一次 `dailyTask` action
- 抽题规则：5 大模块各抽 2 题，难度 2~4
- 数据库查询是随机的，所以每日题目会变
- **联调时如果没等到 00:05**，可以手动触发一次（开发者工具 → 云函数 → timer → 测试 → action=`dailyTask`）

**云函数日志关注**：
- `timer`（dailyTask 跑成功 + 写 daily_task）
- `checkin`（打卡记录写入 + 用户 checkin 字段更新）
- `rank`（rebuildRank 触发后聚合 + 写 rank_cache）

---

### 链路 D：收藏 + 分享

**目标**：验证 favorite 云函数 + share 云函数 + 事件埋点。

| 步骤 | 操作 | 预期 | 异常排查 |
|---|---|---|---|
| D1 | 答题页某题点★收藏 | 该题加入"我的收藏" | 收藏失败 → favorite 云函数异常 |
| D2 | 首页"我的收藏" | 显示收藏题列表 | 列表为空 → 没走云函数，前端直查数据库（违反架构约束） |
| D3 | 取消收藏 | 该题从收藏消失 | 没消失 → toggle 逻辑错 |
| D4 | 答题页右上角"分享"按钮 | 弹出分享卡片（含题 + share_text 配置文案） | 文案是默认值 → share_text 配置没生效 |
| D5 | 真机点"分享给朋友" | 对方能看到卡片标题和图 | 图裂 → onShareAppMessage imageUrl 路径错 |

**云函数日志关注**：`favorite` / `share` 函数的事件写入 events 集合

## 2. 异常链路测试（边界条件）

| 场景 | 操作 | 预期 | 重要性 |
|---|---|---|---|
| 弱网/断网 | 飞行模式提交答案 | 友好提示"网络异常，请重试" | **必须** |
| 重复提交 | 答题页连点"提交"两次 | 后端只算一次（前端防抖 + 后端幂等） | **必须** |
| Token 过期 | 改 miniprogram/config.js 的 envId 触发重新登录 | 自动重新 wx.login | 中 |
| 题目下架 | 直接改数据库 questions.status=0 | 该题不再被抽到，但已收藏/错题本仍能看 | 中 |
| 数据库写冲突 | 同时在两个真机登录同 openid | 后一个的 update应该胜出（事务回滚保护） | 低 |
| 超大题量提交 | answer 单次提交 50 题 | 事务成功，不超时（标准版 900s 足够） | 低 |
| 并发打卡 | 同 openid 多端打卡 | checkin 集合 unique 索引 (`openid_date_unique`) 拦截 | 低 |

## 5. 常见问题排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| 云函数调用返回 401 | OPENID 没拿到，多半是开发工具未登录 | 微信开发者工具点"登录" |
| 数据库操作返回 permission denied | 集合安全规则没改 / 不是 ADMINONLY | 控制台 → 数据库 → 选集合 → 权限 |
| 调用云函数 timeout | 标准版 900s 足够；个人版 3s 必超 | 已升级标准版，问题应消失 |
| 真机扫码白屏 | 主包超过 2MB 或缺文件 | 开发者工具编译时显示包大小 |
| 头像不显示 | chooseMedia 没在 chooseAvatar 里调用 | 用 `open-type="chooseAvatar"` |
| 收藏题点击无反应 | favorite toggle 逻辑没刷本地 | 重新 fetch favorite 列表 |
