## 一、测试环境架构

小程序无法脱离微信开发者工具跑真机渲染，本环境把**可自动化的全部逻辑层**纳入测试：

```
┌─ 静态检查 ──────────────────────────────────────┐
│ app.json 一致性 / 架构不变量 / JSON·JS 语法 /     │
│ 云函数依赖声明 / 设计令牌唯一来源 / 导入数据格式  │
└──────────────────────────────────────────────────┘
┌─ 单元测试（11 个云函数 + 前端模块）──────────────┐
│            mock wx-server-sdk（内存数据库）       │
│  · command 运算符（gte/lt/in/inc/neq/and/sum）    │
│  · 聚合管道（match/group/sort/limit）            │
│  · 事务：快照隔离 + 平台单文档限制（忠实还原）    │
│  · 错误注入（唯一索引冲突 / 网络失败 / 超时）      │
└──────────────────────────────────────────────────┘
┌─ 集成测试（核心用户旅程全链路）──────────────────┐
│  services → mock wx.cloud → 真实云函数代码 →     │
│  mock 数据库，前后端两侧断言数据最终一致          │
└──────────────────────────────────────────────────┘
```

关键设计决策：**mock 层忠实还原平台约束**，而不是「让代码跑过去」——
云开发官方文档明确「事务中不支持批量操作（where 语句），只支持单记录操作
（collection.doc / collection.add）」。模拟层按此抛错，这正是发现 1 号致命缺陷的手段。

## 三、发现并修复的缺陷（9 个）

| # | 级别 | 缺陷 | 修复 |
|---|---|---|---|
| 1 | **致命** | `answer` 事务内用 `where().update()` 更新用户统计——云开发事务只支持单文档操作，**线上每次提交必报「成绩保存失败」**，刷题核心链路整体不可用 | 预查用户档案，事务内改 `doc().update()`；缺档时兜底建档（登录竞态） |
| 2 | **严重** | `user` 云函数**整体缺失**，但首页/我的页/练习页调用其 `stats`/`updateProfile`/`grantSubscribe`——全部静默失败，「我的」页统计永远为空、头像昵称保存无效 | 新建 `cloudfunctions/user`（含字段白名单、64 字符截断、订阅计数） |
| 3 | **严重** | 错题重做链路断裂：wrong 页跳 `practice?scene=review`，但 practice 页不识别 review，走随机抽题；`wrongbook.redraw` 云函数能力从未被任何页面调用 | practice 页支持 review 场景调用错题重做；新建 `services/wrongbook.js` |
| 4 | **严重** | 错题本单题点击失效：wrong 页传 `qid` 参数，practice 页 `onLoad` 直接忽略——点错题 A 出来的是随机题 | practice 页支持 `qid` 单题模式（`question.detail`） |
| 5 | 中 | 新用户难度配比反直觉：无作答数据默认 rate=0.5 → 20% 难题，**比成绩差的用户还难**，与「避免新手被劝退」的注释意图相反 | 无数据默认 rate=0（新手档：易 5 中 5 难 0） |
| 6 | 中 | `wrongbook` `mastered=true` 语义颠倒：意图「查看全部」，实际 `_.neq(false)` 只返回已掌握的 | 该参数时不过滤 mastered 字段 |
| 7 | 低 | 断网提交双 toast（「网络不太给力」+「已保存」连弹）且默认重试 2 次拖 1.2s 才入队 | `submitSafe` 改 silent + retry:0 快速失败 |
| 8 | 低 | 建库文档漏 `rank_cache` 集合（漏建则榜单重建 500） | 文档补齐，10 → 11 个集合 |
| 9 | 低 | `services/answer` 提交时丢弃 `taskId`（云端回显用） | 透传 |

## 四、已知限制（诚实声明）

以下内容**不在本环境覆盖范围内**，需要真机/控制台验证：

1. **渲染与交互层**：WXML/WXSS 实际渲染、swiper 手势、组件生命周期——需开发者工具 + 真机
2. **微信侧能力**：`wx.login` 换 code、`requestSubscribeMessage` 真实授权弹窗、
   `chooseAvatar`/`nickname` 组件、隐私协议 `getPrivacySetting`、分享卡片实际样式
3. **openapi 真实调用**：小程序码生成（`wxacode.getUnlimited`）走 mock，未消耗真实配额
4. **数据库性能**：索引是否生效、百万级数据量下的查询耗时——建议建库后用控制台「索引自检」+ 小批量压测
5. **并发一致性**：模拟层是单线程快照近似，真实快照隔离下的写冲突、事务锁阻塞未验证
6. **订阅消息推送**：`checkin_tmpl_id` 配置后的实际送达链路

## 五、验收建议

```bash
npm test          # 全量：134 用例，约 8 秒
npm run test:unit # 仅单元
npm run test:integration # 仅集成
```

你试用时建议重点走查（按修复的缺陷对应）：
1. **刷一道题提交**——修复前必报「成绩保存失败」，现在应秒出对错与解析
2. **「我的」页统计与头像昵称保存**——修复前永远为空
3. **错题本 → 重做 / 点单题**——修复前出的是随机题
4. 断网开关：飞行模式答一题，恢复后自动补交
