## 1.3 timer 健康监控（healthCheck 触发器）

**目的**：每天自动巡检关键集合状态，异常时自动记录到 events 集合，无需人工查询。

### 配置

- **云函数**：`timer`（与 dailyTask / rebuildRank / archive 共用同一个云函数，通过 action 路由）
- **触发器**：`healthCheck` cron `0 10 9 * * * *`（**每天 09:10**，晚于 dailyTask 00:05 九小时留容错窗口）
- **新增代码**：`cloudfunctions/timer/index.js` 的 `handleHealthCheck` 函数（2026-09-06 添加）

### 巡检 4 项

| 检查项 | 通过条件 | 失败后果 |
|---|---|---|
| `daily_task_today` | `daily_task` 集合今日有 1 条记录 | 每日题没生成 → 用户打卡异常 |
| `rank_cache_any` | `rank_cache` 集合至少 1 条记录 | 榜单为空 → 排行榜页空白 |
| `records_count` | `records` 总条数 < 1,000 万 | 容量爆表（500 万 warn / 1000 万 error） |
| `users_count` | 不算失败，仅记录 | 用户量指标 |

### 异常处理流程

1. 任一子项失败 → 写一条 `type=health_alert` 到 `events` 集合（**自动，无需人工**）
2. 记录内容包含：`level` (warn/critical) + 失败的检查项名 + 完整 checks 数组
3. 用户通过以下方式查看：
   - CloudBase Web 控制台 → 数据库 → events 集合 → 查 `type=health_alert` 记录
   - CLS 日志：函数 timer 输出
   - （未来）管理后台页面读 events 展示

### 手动触发（联调期间）

```bash
# MCP 通道（AI 调试用）
mcp__cloudbase__manageFunctions action=invokeFunction functionName=timer \
  params='{"action":"healthCheck","payload":{}}'

# 微信开发者工具
云函数 → timer → 测试 → action=healthCheck → 运行
```

### 部署方式（增量更新，不丢触发器）

```bash
# MCP 通道（**必须**用 updateFunctionCode 而不是 createFunction force=true，
# 后者会清掉所有已有触发器）
mcp__cloudbase__manageFunctions action=updateFunctionCode force=true \
  functionName=timer \
  func='{"name":"timer","handler":"index.main","runtime":"Nodejs18.15","timeout":20}' \
  functionRootPath="/Users/licetus_meta/WorkBuddy/xingce-assistant/cloudfunctions"
```

### 经验教训

- **`createFunction force=true` 会清空所有触发器**。改代码必须用 `updateFunctionCode`
- **`invokeFunction` 是 AI 调试神器**：能直接调云函数，传 `{action, payload}`，传 OPENID 时会自动注入
- **`force=false` 时 updateFunctionCode 可能静默跳过**：如果代码哈希没变，MCP 不会真正部署
  - 当前 deploy CI 流程建议**永远用 `force=true`**

## 1.4 CI 工作流（GitHub Actions）

**目的**：每次 push / PR 自动跑 npm test，可选跑云开发健康检查。

### 配置文件

- `.github/workflows/ci.yml`：GitHub Actions 工作流（已提交）
- `scripts/cloudbase-healthcheck.js`：CI 用脚本，调 timer.healthCheck action

### 两个 Job

| Job | 触发条件 | 作用 |
|---|---|---|
| `test` | 每次 push/PR | 跑 `npm test`（Node 18 / 20 / 22 三版本矩阵） |
| `cloudbase-healthcheck` | 仅 push 到 develop | 调 timer.healthCheck，依赖 2 个 secret |

### GitHub Secrets 配置（让 healthcheck job 启用）

进入 repo → Settings → Secrets and variables → Actions → New repository secret：

| Secret 名 | 来源 |
|---|---|
| `TENCENTCLOUD_SECRETID` | 腾讯云访问管理 → API 密钥管理 → SecretId |
| `TENCENTCLOUD_SECRETKEY` | 同上 SecretKey |

> 不配 secret 时 healthcheck job 会跳过（exit code 2，CI 标绿但会在日志里说"缺少环境变量"）。
> 安全提示：SecretKey 权限要最小化——只给 `QcloudTCBFullAccess` 或更细的策略。

### 本地手动跑 healthcheck

```bash
# 装一次（不写 package.json；项目零运行时依赖，sdk 仅 CI 用）
# 推荐装到全局 workspace，避免污染项目目录
cd ~/.workbuddy/binaries/node/workspace && npm install @cloudbase/node-sdk

# 配环境变量
export TENCENTCLOUD_SECRETID=AKIDxxxxx
export TENCENTCLOUD_SECRETKEY=xxxxx
export CLOUD_ENV_ID=pro-d3g3e4uab0265b1c6

# 跑（用 NODE_PATH 让脚本找到全局装的 sdk）
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  node scripts/cloudbase-healthcheck.js
```

**退出码对照**：
- `0` = 全部健康
- `1` = healthCheck 有 failed 项
- `2` = 缺 secret（CI 没配）
- `3` = 调用异常

## 4. 开通 CLS 日志（必须做）

### 4.1 为什么必须做

不开通 CLS，云函数 / 数据库 / 网关的所有运行日志都看不到。线上出问题 = 黑盒。体验版配额够联调期，**不要省这一步**。

### 4.2 腾讯云不开放 API

⚠️ **TCB 日志服务不开放 API 开通**，必须走 Web 控制台或微信开发者工具。本工具链已确认：

- `mcp__cloudbase__queryLogs` `checkLogService` → 当前 `enabled: false`
- `mcp__cloudbase__callCloudApi` 调 `tcb.SearchClsLog` → `action invalid`
- 腾讯云 TCB API 概览（876/34809）搜索日志分类仅有 `BindCls`/`SearchClsLog`/`ModifyClsTopic`，无 `CreateLogService`
- 腾讯云 CLS 文档明确：TCB 日志主题"开启日志服务时创建，**不开放接口**"

### 4.3 控制台开通步骤（5 分钟）

1. 打开 [CloudBase 控制台](https://console.cloud.tencent.com/tcb) → 顶部选择「上海」
2. 左侧菜单「环境」→ 找到 `datizhushou` → 进入
3. 左侧菜单「设置」→「日志服务」
4. 点击「立即开通」→ 等待 1-2 分钟（创建日志集 + 主题 + 索引）
5. 开通后回到本节顶部再次确认：本仓库 `mcp__cloudbase__queryLogs action=checkLogService` 应返回 `enabled: true`

### 4.4 开通后立即做的

CLS 开通后，云函数默认会**自动把 stdout/stderr 推送到 CLS**。但每个函数的 `ClsLogsetId` / `ClsTopicId` 可能为 `""`（本次部署查到的 timer 函数这两个字段就是空）。需要：

- **方案 A（推荐）**：在 CloudBase 控制台「云函数 → 选择函数 → 函数配置 → 日志配置」手动给每个函数绑同一组 logset/topic
- **方案 B（自动化）**：写一个 `scripts/bind-cls-to-functions.js` 脚本，循环调 `mcp__cloudbase__manageFunctions` 的 update 接口批量绑定（需要 CLS 创建后才有 logset/topic ID，先 §4.3 再 §4.4）

> **等开通完成后告知开发者，本节以下动作可立即执行。**

## 5. 配置告警（开通 CLS 后做）

### 5.1 推荐告警规则

| 规则名 | 查询语句 | 阈值 | 通知 |
|---|---|---|---|
| 云函数 ERROR 突增 | `module:function AND level:error` | 5 分钟 ≥ 3 条 | 紧急 |
| 云函数超时 | `module:function AND status_code: 504` | 5 分钟 ≥ 5 条 | 紧急 |
| 慢查询（文档库） | `module:database AND eventType:MongoSlowQuery` | 5 分钟 ≥ 10 条 | 警告 |
| 网关 QPS 接近上限 | `metric:GatewayEnvQPS` | ≥ 400（体验版上限 500） | 警告 |
| DB 容量 | `metric:DbSizepkg` | ≥ 80% 配额 | 警告 |

### 5.2 通知渠道优先级

1. **企业微信机器人 webhook**（最及时，免费，强烈推荐）
2. **邮件**（兜底，免费）
3. **短信**（仅最紧急事件，体验版无短信通道，正式版才开）

### 5.3 配企业微信机器人

1. 拉一个群（或现有运维群）→ 「群设置 → 群机器人 → 添加」→ 复制 webhook
2. 腾讯云控制台「[消息中心](https://console.cloud.tencent.com/message) → 消息订阅 → 通知渠道」→ 添加「企业微信机器人 webhook」
3. 验证：发一条测试消息，群里应能看到腾讯云 logo
4. 在 CLS 控制台「告警 → 通知模板」选这个渠道 + §5.1 规则

## 10. 常见问题

### Q1：日志搜不到？
先 `mcp__cloudbase__queryLogs action=checkLogService` → 必须 `true`。
`module:function` 查的是云函数日志；`module:database` 查的是数据库；`logType:accesslog` 查的是网关访问日志。

### Q2：函数超时 504？
体验版超时 20s，复杂判题可能不够。临时方案：在 `cloudbaserc.json` 把该函数 `timeout` 调到 60；
根本方案：升标准版（300s）。

### Q3：找不到题？
- 检查 `questions` 集合的 `status` 字段是否为 1
- 检查 `module` 字段是否对应五大模块名（`常识判断` / `言语理解` / `数量关系` / `判断推理` / `资料分析`，**全中文无空格**）
- 索引是否齐全：`listIndexes questions` 应返回 5 条

### Q4：定时任务没跑？
- 触发器必须 enabled（`queryFunctions action=listFunctionTriggers functionName=timer`）
- Cron 表达式：腾讯云用 7 段（秒 分 时 日 月 周 年），比标准 cron 多 1 段
- 查上次执行：控制台「云函数 → timer → 日志」筛 timer 关键字

### Q5：体验版到 2027-03-06 怎么办？
必须升标准版。环境不会自动销毁，但升级前会有邮件 / 短信通知。
