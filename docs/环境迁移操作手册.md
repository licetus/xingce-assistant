## 3. ⚠️ 用户必须手动完成（5 个动作）

### 3.1 业务索引（最关键）

**MCP 工具的 `updateCollection CreateIndexes` 数组有 schema 解析 bug**，无法通过 MCP 建业务复合索引。

**手工方案 A（CloudBase Web 控制台，最快）**：

1. <https://console.cloud.tencent.com/tcb> → 上海 → `pro-d3g3e4uab0265b1c6` → 数据库
2. 选集合 → 索引管理 → 「新增索引」
3. 按下表 18 条业务索引逐条建

**手工方案 B（tcb CLI，登录后一行命令）**：

```bash
tcb login  # 扫码一次
tcb db updateCollection --envId pro-d3g3e4uab0265b1c6 --collectionName users \
  --createIndexes '[{"IndexName":"openid_unique","MgoKeySchema":{"MgoIndexKeys":[{"Name":"_openid","Direction":"1"}],"MgoIsUnique":true}}]'
```

**索引清单**（按集合，标 ✅ 的为 CloudBase 默认已建）：

| 集合         | 索引名                        | 字段                          | 唯一 | 备注   |
| ---------- | -------------------------- | --------------------------- | -- | ---- |
| users      | `_id_`                     | _id                         |    | ✅ 默认 |
| users      | `_openid_1`                | _openid                     |    | ✅ 默认 |
| users      | `openid_unique`            | _openid                     | ✓  | 业务   |
| questions  | `qid_unique`               | qid                         | ✓  | 业务   |
| questions  | `module_status_difficulty` | module, status, difficulty  |    | 业务   |
| questions  | `module_difficulty`        | module, difficulty          |    | 业务   |
| qgroups    | `module_unique`            | module                      | ✓  | 业务   |
| records    | `openid_date`              | _openid, date(desc)         |    | 业务   |
| records    | `openid_module_date`       | _openid, module, date(desc) |    | 业务   |
| records    | `date`                     | date                        |    | 业务   |
| wrong_book | `openid_qid_unique`        | _openid, qid                | ✓  | 业务   |
| wrong_book | `openid_lastWrongAt`       | _openid, lastWrongAt(desc)  |    | 业务   |
| favorites  | `openid_qid_unique`        | _openid, qid                | ✓  | 业务   |
| favorites  | `openid_createdAt`         | _openid, createdAt(desc)    |    | 业务   |
| checkins   | `date_correctCount`        | date, correctCount(desc)    |    | 业务   |
| checkins   | `openid_date_unique`       | _openid, date               | ✓  | 业务   |
| daily_task | `date_unique`              | date                        | ✓  | 业务   |
| config     | `key_unique`               | key                         | ✓  | 业务   |
| events     | `type_createdAt`           | type, createdAt(desc)       |    | 业务   |

> ⚠️ **rank_cache 不要建 `_openid` 唯一索引**（2026-09-07 已删除曾误建的 `openid_unique`）：
> 该集合只有 `week`/`total` 两条固定 `_id` 的缓存文档，都不含 `_openid` 字段，
> 唯一索引会把两条缺失值都算作 null，第二条写入必报 E11000 duplicate key，
> 导致每小时 rebuildRank 定时任务持续失败。

### 3.3 定时触发器（个人版不支持）

**个人版限制：没有 timer 触发器配额。** 3 个原计划（dailyTask / rebuildRank / archive）**全部建不了**。

**降级方案**：

- **dailyTask**（每日 00:05 生成 10 题）：改为 `checkin` 云函数在用户首次打卡时按需生成
- **rebuildRank**（每小时刷新榜单缓存）：改为 `rank` 云函数在用户查榜单时**实时聚合**（小规模下可承受）
- **archive**（90 天前 records 归档）：90 天后再考虑，或升级标准版后立即建

代码改动清单（待办）：

- `cloudfunctions/checkin/index.js`：在 `handleCheckin` 入口先尝试 `db.collection('daily_task').where({date: today}).get()`，若空则随机抽 10 道补上
- `cloudfunctions/rank/index.js`：移除 `action=rebuild` 分支（无人调），改为强制实时聚合
- `cloudfunctions/timer/`：可以**删除**整个目录（不删也行，反正不会跑）
