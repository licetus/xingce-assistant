# 数据库导入说明

> 建库是联调的前提：集合不存在，云函数会直接报错。
> 按顺序做一遍，约 20 分钟。

## 导入前必读：JSON 格式要求

云开发控制台导入的 JSON **必须是 JSON Lines 格式**：

```
{"qid":10001,"module":"言语理解","stem":"..."}
{"qid":10002,"module":"数量关系","stem":"..."}
```

- 每行一个完整对象，用换行 `\n` 分隔
- **不是**标准 JSON 数组（不能用 `[ {...}, {...} ]`，也不能缩进美化）
- 文件必须 UTF-8 编码
- 键名首尾不能是 `.`，不能含连续 `.`
- 时间字段用 ISODate：`"date": { "$date": "2026-08-31T17:30:00.882Z" }`

写错格式控制台会直接报「格式错误」，导入失败。
`scripts/import-questions.js` 已按此格式输出，直接用它的产物即可。

---

## 第一步：建集合（10 个）

在云开发控制台 → 数据库 → 集合管理，逐个新建：

| 集合 | 用途 | 本目录是否有导入文件 |
|---|---|---|
| `users` | 用户主档与统计 | 否（首次登录自动创建） |
| `questions` | 题库 | ✅ `questions_*.json` |
| `qgroups` | 材料题共用材料 | 否（无材料题时可不建） |
| `records` | 答题流水 | 否（作答自动写入） |
| `wrong_book` | 错题本 | 否（判题自动写入） |
| `favorites` | 收藏 | 否（收藏自动写入） |
| `checkins` | 每日打卡 | 否（打卡自动写入） |
| `daily_task` | 每日任务题集 | 否（`timer` 云函数每日生成） |
| `config` | 运营配置 | ✅ `config.json` |
| `events` | 埋点流水 | 否（`track` 自动写入） |

建完集合后，把 `config.json` 和 `questions_*.json` 分别导入对应集合，
冲突处理模式选 **Upsert**（重复导入时更新而非报错）。

## 第二步：设安全规则（关键，别漏）

**每个集合的安全规则都要改成「仅管理端可读写」。**

默认规则是「仅创建者可读写」，客户端就能绕过云函数直连数据库，
题库可被批量拖走。这是本项目最重要的安全设置。

改法：集合 → 权限设置 → 自定义安全规则 → 选择「仅管理端可读写」。

## 第三步：建索引（16 条）

照 `../indexes.md` 的表格逐条建。

其中两条**唯一索引承担业务约束，不能省**：

- `favorites` 的 `_openid + qid` —— 防重复收藏
- `checkins` 的 `_openid + date` —— 防重复打卡

不建这两条，用户狂点按钮会产生重复数据。其余索引是性能需要，
数据量小时感觉不到，涨到百万级缺一个就是全表扫描、云函数超时。

## 第四步：导入题库

```bash
node scripts/import-questions.js <你的题库.csv 或 题库.json>
```

脚本会校验、清洗、按 500 题切片输出到 `database/import/`。
CSV 表头格式见 `scripts/sample-questions.csv`。

题库字段含义见 `../schema.md`。

---

## 导入后的自检

1. `config` 集合有 5 条记录，`audit_mode` 为 `false`
2. `questions` 集合题量与预期一致
3. 任意集合点「权限设置」，确认是「仅管理端可读写」
4. `questions` 集合的 `qid` 索引状态为「已生效」而非「建立中」

第 4 条容易被忽略：索引在数据量较大时需要后台构建，
状态是「建立中」时查询仍会全表扫描，等它变成「已生效」再压测。
